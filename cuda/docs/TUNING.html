Parameter Overview

The SMC² system has several interconnected parameters. Tuning is not independent — changes to one parameter often require adjustments to others.

Parameter Symbol Default Affects
θ-particles N_theta 256 Posterior resolution, GPU occupancy
Inner particles N_inner 256 Likelihood variance, memory
Fixed-lag window L 100 Bias vs variance, memory
CPMMH correlation ρ_cpmmh 0.99 Acceptance rate, exploration
Outer ESS threshold τ_outer 0.5 Rejuvenation frequency
Inner ESS threshold τ_inner 0.5 Resampling frequency
Drift matrix Q See below Regime adaptation speed
Liu-West shrinkage a 0.98 Particle diversity
Rule of Thumb

Start with defaults. Only tune when diagnostics indicate a problem. Tune one parameter at a time and observe the effect for at least 1000 ticks before adjusting another.

Particle Counts

N_theta (θ-particles)

Controls the resolution of the parameter posterior. More particles = better approximation of the true posterior, but diminishing returns beyond ~512.

N_theta Memory Quality Use Case
64 ~25 MB Marginal Debugging, quick tests
128 ~50 MB Acceptable Development, prototyping
256 ~100 MB Good Production (recommended)
512 ~200 MB Excellent High-accuracy requirements

N_inner (Inner particles per θ)

Controls the variance of the likelihood estimate. More inner particles = lower variance = more stable acceptance rates in CPMMH.

N_inner Likelihood σ Accept Rate Impact
64 High (~2-3) Erratic, needs high ρ_cpmmh
128 Medium (~1-2) Workable with ρ_cpmmh=0.99
256 Low (~0.5-1) Stable, good mixing
512 Very low (~0.3) Very stable, diminishing returns
Total particles = N_theta × N_inner = 256 × 256 = 65,536
GPU Occupancy

For best GPU utilization, keep N_theta as a multiple of 32 (warp size) and N_inner as a power of 2. The product should be at least 32,768 for good throughput on modern GPUs.

Fixed-Lag Window (L)

The fixed-lag parameter L controls how much history CPMMH replays during rejuvenation. Larger L = less bias but more variance and compute.

Bias-Variance Tradeoff

Bias ≈ ρL     (decays exponentially with L)
ρ (persistence) L = 50 L = 100 L = 200 Recommended L
0.90 0.5% bias 0.003% ~0% 50
0.95 7.7% bias 0.6% 0.003% 100
0.99 60% bias 37% 13% 200-300

Memory Impact

Circular buffer size = N_theta × N_inner × (L + 1) × 2 bytes (FP16)

L Buffer Size (256×256) Replay Time
50 6.7 MB ~5 ms
100 13.1 MB ~10 ms
200 26.2 MB ~20 ms
Rule of Thumb

Set L ≈ 7 × half-life, where half-life = log(0.5) / log(ρ). For ρ = 0.95, half-life ≈ 14, so L ≈ 100 is appropriate.

CPMMH Correlation (ρ_cpmmh)

The correlation parameter controls how similar the random numbers are between current and proposed particle filters. Higher correlation = lower variance in likelihood ratio = higher acceptance rate.

More exploration More acceptance
ρ = 0.90 ρ = 0.95 ρ = 0.99 ρ = 0.999
ρ_cpmmh Expected Accept % Exploration When to Use
0.90 15-25% High Low N_inner, need diversity
0.95 30-40% Medium Balanced
0.99 45-55% Low-Medium Default, stable operation
0.999 55-65% Low High N_inner, acceptance too low
Is your acceptance rate below 30%?
Yes → Increase ρ_cpmmh Try 0.995 or 0.999. If still low, increase N_inner.
No → Check exploration If params aren't moving, decrease ρ_cpmmh to 0.95.

Drift Matrix Q

The drift matrix Q controls how much parameters can change per rejuvenation. This is the key to adapting to regime changes.

Per-Parameter Values

Parameter Typical Posterior σ Q_sqrt (default) Q_sqrt (aggressive)
ρ (persistence) 0.015 - 0.025 0.005 0.01
σ_z (z innovation) 0.03 - 0.08 0.01 0.02
μ_base (vol mean base) 0.3 - 0.6 0.1 0.2
μ_scale (vol mean scale) 0.3 - 0.6 0.1 0.2
μ_rate (vol mean rate) 0.1 - 0.3 0.05 0.1
σ_base (vol-of-vol base) 0.05 - 0.15 0.02 0.05
σ_scale (vol-of-vol scale) 0.05 - 0.15 0.02 0.05
σ_rate (vol-of-vol rate) 0.1 - 0.3 0.05 0.1

Adaptive Q Scaling

Scale Q based on filter stress (NLL excess):

// Stress factor: 1.0 (calm) to 2.0+ (stressed)
float stress = 1.0f + nll_excess_accum / 50.0f;
stress = fminf(stress, 3.0f);  // Cap at 3x

for (int p = 0; p < 8; p++) {
    Q_effective[p] = Q_base[p] * stress;
}
Tuning Strategy

Start with conservative Q values. If regime changes take too long to detect (high NLL persists for 500+ ticks), increase Q. If parameters oscillate unnecessarily during stable periods, decrease Q.

Liu-West Regularization

After resampling, particles may collapse to duplicates. Liu-West regularization maintains diversity through shrinkage + jitter.

θ'[j] = a · θ[j] + (1-a) · μ_θ + h · Chol(Σ_θ) · ε

where h² = 1 - a² to preserve total variance.

Shrinkage (a) Jitter (h) Behavior
0.90 0.436 High jitter, fast adaptation, may over-disperse
0.95 0.312 Moderate jitter, good balance
0.98 0.199 Default: stable, sufficient exploration
0.99 0.141 Conservative, slow adaptation
Interaction with Q

Liu-West jitter and drift Q both add exploration. If using both, you may want smaller values for each. If using only one, increase its magnitude.

Diagnostic Formulas

Effective Sample Size

ESS = 1 / Σ w[j]²

Measures particle diversity. ESS/N < 0.5 triggers rejuvenation.

Z-score

z = |θ_est - θ_true| / σ_posterior

Measures statistical consistency. z < 2 means truth is within 95% CI.

NLL Excess

excess = max(0, nll - baseline)

Accumulated evidence of parameter mismatch.

Tuning Recipes

Recipe 1: Fast Adaptation (HFT)

Prioritize speed of regime detection over parameter precision.

N_theta     = 128
N_inner     = 128
L           = 50
ρ_cpmmh     = 0.99
Q_sqrt      = 2× default  // More drift
a           = 0.95        // More jitter
τ_outer     = 0.6         // More frequent rejuvenation

Recipe 2: High Accuracy (Research)

Prioritize parameter precision over adaptation speed.

N_theta     = 512
N_inner     = 512
L           = 200
ρ_cpmmh     = 0.995
Q_sqrt      = 0.5× default  // Less drift
a           = 0.99          // Less jitter
τ_outer     = 0.4           // Less frequent rejuvenation

Recipe 3: Balanced (Default)

Good tradeoff for most production use cases.

N_theta     = 256
N_inner     = 256
L           = 100
ρ_cpmmh     = 0.99
Q_sqrt      = default
a           = 0.98
τ_outer     = 0.5

Recipe 4: Memory Constrained

For GPUs with limited VRAM (< 4GB).

N_theta     = 128
N_inner     = 128
L           = 64
ρ_cpmmh     = 0.995        // Higher to compensate for fewer particles
Q_sqrt      = 1.5× default
a           = 0.97

// Total memory: ~25 MB (vs ~100 MB default)

Troubleshooting

Acceptance rate too low (< 30%)?
Fix → 1. Increase ρ_cpmmh (try 0.995)
2. Increase N_inner (try 512)
3. Decrease proposal scale
If > 60% → Decrease ρ_cpmmh to explore more
Parameters not tracking regime change?
Fix → 1. Increase Q (2× default)
2. Decrease a (try 0.95)
3. Enable adaptive Q scaling
If oscillating → Decrease Q, increase a
ESS collapsing frequently?
Fix → 1. Increase N_inner
2. Decrease τ_outer (try 0.4)
3. Check for model misspecification
If rarely rejuvenating → Increase τ_outer (try 0.6)
NLL spiking and not recovering?
Fix → 1. Major regime change — increase Q dramatically
2. Consider resetting filter with fresh prior
3. Check data for anomalies
If slowly rising → Gradual drift — enable adaptive Q
When All Else Fails

If the filter is severely misaligned (NLL > 2× baseline for 500+ ticks), it may be faster to reinitialize from the prior rather than wait for drift to correct. This is a design choice: how much "memory" do you want to preserve vs. how quickly do you need to adapt?
