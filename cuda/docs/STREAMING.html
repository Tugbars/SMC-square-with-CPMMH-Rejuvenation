∞ The Three Infinity Problems

When running SMC² continuously on streaming data (T → ∞), three fundamental problems emerge:

1. Memory Explosion

Noise arrays grow O(T). At T=100,000 ticks with 256×256 particles: 26 GB of random numbers.

2. Weight Collapse

Old likelihood accumulates. After 50,000 ticks, new data barely moves the needle — the past drowns out the present.

3. Regime Lock-in

Parameters calibrated on calm markets dominate forever. Even during a crisis, θcalm particles have insurmountable accumulated likelihood.

Traditional approaches use a forgetting factor λ to discount old observations. But this fundamentally misunderstands the problem.

λ Why Forgetting Fails

The Inertia Trap

The forgetting factor λ applies exponential decay to weights:

log w[j] = Σt λT-t · log p(yt | θj)

This makes old data "matter less" — but it doesn't create new particles. If θcrisis isn't in your support set, no amount of re-weighting will find it.

After 10,000 observations, posterior is SHARP:

  p(θ)
    ▲          │
    │          █
    │          █     ← All 256 θ-particles concentrated here
    │         █ █
    │        █   █
    │      ██     ██
    └──────────────────────────────────────▶ θ
             θcalm                    θcrisis

After regime change to crisis:

  p(θ)
    ▲          │                       │
    │          █                       │
    │          █   ← Particles stuck   │ ← True params (no particles!)
    │         █ █                      │
    └──────────────────────────────────────▶ θ
             θcalm                    θcrisis

Forgetting makes us "less confident" in θcalm
but doesn't help us FIND θcrisis
Critical Insight

Forgetting factors only manipulate weights. They cannot create new values. You must physically move the particles to explore new regions of parameter space.

Δ The Solution: Parameter Drift

From Static to Time-Varying

Instead of treating parameters as static constants estimated from data, we model them as slowly evolving state:

Static Model (Current)

θ = constant

Parameters never change. We just estimate them better over time.

Drifting Model (Proposed)

θt = θt-1 + wt,   wt ~ N(0, Q)

Parameters can genuinely change. We track their evolution.

Why Drift Solves the Problem

The Key Difference

Forgetting lowers confidence in the old estimate. Drift actively explores the parameter space near the current estimate. If the market shifts, the "inflated" particle cloud captures the new regime much faster.

Σ Bayesian Compression

We don't need to remember all past observations — just compress our knowledge into a sufficient statistic.

A

Compress: Particle Cloud → Moments

At time t, compute weighted mean μθ and covariance Σθ from the particle population. This is your "compressed knowledge" — everything learned from y1:t.

B

Inflate: Add Process Noise

Before processing new data, inflate uncertainty: Σinflated = Σθ + Q. The matrix Q represents the "rate of parameter chaos" — how much true parameters might drift per time step.

C

Explore: CPMMH with Inflated Proposal

Use the inflated covariance for CPMMH proposals: θ' = θ + Chol(Σinflated) · ε. This explicitly tells the chain: "explore outside the current confidence interval."

θt+1 | θt ~ N(θt, Q) → Σt+1|t = Σt + Q

◈ Piecewise-Static Architecture

We treat parameters as piecewise static: constant during forward filtering blocks, allowed to jump only during rejuvenation. This maximizes GPU throughput while maintaining adaptability.

for each tick t:

  1. FORWARD STEP (parallel, all Nθ × Ninner particles)
     ┌─────────────────────────────────────────────────────────────┐
     │  Propagate (z, h) for each (θ-particle, inner-particle)     │
     │  Update weights based on p(yt | ...)                       │
     │  Inner resample + sort if needed                            │
     │  Accumulate outer log-likelihood                            │
     └─────────────────────────────────────────────────────────────┘

  2. OUTER ESS CHECK
     if ESS < threshold:

       2a. COMPRESS: Compute (μθ, Σθ) from particles
           ┌───────────────────────────────────────────────────┐
           │  μθ = Σ w[j] · θ[j]                              │
           │  Σθ = Σ w[j] · (θ[j] - μθ)(θ[j] - μθ)ᵀ        │
           └───────────────────────────────────────────────────┘

       2b. INFLATE: Add drift covariance
           ┌───────────────────────────────────────────────────┐
           │  Σinflated = Σθ + Q                             │
           │                                                   │
           │  Q = diag(qρ², qσz², qμbase², ...)            │
           │      "rate of parameter chaos"                    │
           └───────────────────────────────────────────────────┘

       2c. RESAMPLE θ-particles (multinomial)

       2d. CPMMH REJUVENATION with inflated proposal
           ┌───────────────────────────────────────────────────┐
           │  For each θ-particle j:                           │
           │    θ' = θ[j] + Chol(Σinflated) · ε               │
           │    Replay filter [t-L, t] with correlated noise   │
           │    MH accept/reject                               │
           └───────────────────────────────────────────────────┘

       2e. REGULARIZE (Liu-West style, optional)
           ┌───────────────────────────────────────────────────┐
           │  θ[j] = a·θ[j] + (1-a)·μθ + h·Chol(Σθ)·ε       │
           │  Shrink toward mean + jitter                      │
           └───────────────────────────────────────────────────┘

  3. UPDATE CHECKPOINT (circular buffer)
Engineering Insight

Drift at every tick (Option A) is mathematically cleaner for a true time-varying model, but performance suicide on GPU. It breaks coalesced memory access patterns and CPMMH coupling too frequently. Drift at rejuvenation only is the correct engineering compromise.

○ Memory-Bounded: Circular Buffers

For true streaming (T → ∞), we can only store the last L+1 noise values needed for fixed-lag CPMMH replay:

NOISE ARRAYS: Only store last L+1 values (circular buffer)

Fixed-lag L = 100:

Index:    0    1    2   ...   99   100   0    1    2   ...
         ┌────┬────┬────────┬────┬────┐
t=0:     │ n₀ │    │        │    │    │
t=1:     │ n₀ │ n₁ │        │    │    │
...      │    │    │        │    │    │

Compare to T=100,000: 26 GB — 1000× reduction!

Circular Buffer Indexing

The tricky part is mapping absolute time to circular buffer indices during CPMMH replay:

⟲ Liu-West Regularization

After resampling, particles can collapse to duplicates. The Liu-West kernel smoothing trick maintains diversity through shrinkage + jitter:

θ'[j] = a · θ[j] + (1-a) · μθ + h · Chol(Σθ) · ε
Term Purpose Effect
a · θ[j] Retain particle identity Particles stay near their original values
(1-a) · μθ Shrink toward mean Prevents over-dispersion
h · Chol(Σθ) · ε Jitter Maintains exploration / diversity

The magic: when h² = 1 - a², the total variance is preserved:

Var[θ'] = a² · Var[θ] + h² · Var[θ] = Var[θ]
Typical Values

Use a = 0.95-0.99 (shrinkage) and h = √(1-a²) ≈ 0.1-0.3 (jitter). Higher a means more "memory" of individual particle positions; lower a means more regression to the mean.

Q Tuning the Drift Matrix

Q represents "how much can θ change per rejuvenation event." This is the most important hyperparameter.

Parameter Typical σ Qsqrt suggestion Rationale
ρ 0.02 0.005 Persistence changes slowly
σ_z 0.05 0.01 Vol-of-stress can shift
μ_base 0.5 0.1 Baseline vol can move
μ_scale 0.5 0.1 Stress response can change
μ_rate 0.2 0.05 Curve shape fairly stable
σ_base 0.1 0.02 Vol-of-vol baseline
σ_scale 0.1 0.02 Vol-of-vol stress response
σ_rate 0.2 0.05 Curve shape fairly stable

Adaptive Q

Scale Q based on filter stress (NLL excess):

float stress_factor = 1.0f + nll_excess_accum / 50.0f;  // 1.0 to 2.0+

for (int p = 0; p < 8; p++) {
    Q_effective[p] = Q_base[p] * stress_factor;
}

When the filter is struggling (high NLL), inflate Q more → explore faster → adapt to new regime.

▸ Implementation Priority

1

Circular Buffers + Fixed Lag Logic High Priority

Get the "infinite running" capability working first with static parameters. Without this, memory explodes at large T.

2

Drift-Augmented CPMMH High Priority

Implement covariance calculation (μθ, Σθ) and injection of Q into the CPMMH proposal. This is the "brain" that allows learning.

3

Liu-West Regularization Medium Priority

Prevents particle collapse after resampling. Important for maintaining diversity over long runs.

4

Adaptive Q (NLL-based) Optimization

Scale drift based on filter stress. Start with fixed conservative Q values, then add adaptivity if needed.
